Two rules the layout enforces. graph/nodes/ may import from services/, never the reverse, and services/* never imports langchain or langgraph — which keeps the deterministic core testable without a graph runtime and without a model, and is what makes the fallbacks in §6 honest rather than aspirational. And nothing below ui/ imports streamlit: the page is the only module that knows it is a page, so putting a service in front of the same graph later changes nothing underneath it.

There is no api/ package and no separate frontend. app.py calls the compiled graph in the same process (C-03), so no module in this tree imports a web framework.

4  Graph construction and matrices

class StoreGraph:
    nodes: dict[str, Node]          # id → Node
    index: dict[str, int]           # id → matrix row/col
    rev:   list[str]                # matrix index → id

class RouteEngine:
    D_full: np.ndarray              # (V, V) float64 — distances, all edges
    P_full: np.ndarray              # (V, V) int32   — predecessors
    D_step: np.ndarray              # same, lift-only subgraph
    P_step: np.ndarray

    def build(self, g: StoreGraph) -> None: ...
    def distance(self, u: str, v: str, step_free: bool = False) -> float: ...
    def path(self, u: str, v: str, step_free: bool = False) -> list[str]: ...
    def invalidate(self, disabled: list[EdgeRef]) -> None: ...   # EC-30

Build:

csr  = build_csr(g)                 # effective weight = weight_m + penalty_m
D, P = shortest_path(csr, method="D", directed=True, return_predecessors=True)

Path reconstruction:

def path(self, u, v, step_free=False):
    P = self.P_step if step_free else self.P_full
    i, j = self.g.index[u], self.g.index[v]
    if i == j:
        return [u]                                  # EC-25, zero-length
    if P[i, j] == NO_PATH:                          # NO_PATH = -9999
        raise UnreachableNodeError(u, v)            # EC-29
    out, k = [v], j
    while k != i:
        k = int(P[i, k])
        out.append(self.g.rev[k])
    return list(reversed(out))
QuantityValue
Nodes V~300 (216 racks + aisle ends + cross-aisle + 6 cores + entrance + tills)
Edges E~700, directed
Build cost~1M operations per run, two runs, well under a second
MemoryD 720 KB + P 360 KB per matrix, ~2 MB for both pairs
Query costdistance O(1); path O(len), ~15 hops

5  Graph state

class JourneyState(TypedDict):
    # request, written once
    store_id:   str
    raw_query:  str
    mode:       Literal["auto", "single", "multi"]
    start_node: str
    step_free:  bool

    # classification
    shape:  Literal["too_short", "digits", "batch", "nl", "term"]
    terms:  list[SearchTerm]                 # {text, qty}
    parsed: ParsedQuery | None

    # resolution
    candidates:  dict[str, list[Product]]    # term → ranked candidates
    resolved:    dict[str, str]              # term → chosen SKU
    unresolved:  list[str]                   # matched nothing — EC-08
    not_ranged:  list[str]                   # real but not stocked here — EC-04

    # availability and location
    availability: dict[str, StockPosition]
    locations:    dict[str, list[Placement]]
    substitutes:  dict[str, list[Product]]

    # basket — the input to routing
    basket: Annotated[list[BasketItem], merge_basket]

    # output
    route:      Route | None
    directions: list[str]

    # control
    clarify_rounds: int                                 # capped at 2 — EC-35
    degraded:  Annotated[list[str], operator.add]       # nodes that fell back
    errors:    Annotated[list[JourneyError], operator.add]
    verified:  bool                                     # set by verify — EC-47
    mismatches: Annotated[list[Mismatch], operator.add] # claim, expected, found

Three fields earn their place:

  • basket carries a custom reducer rather than operator.add, because two concurrent adds of the same SKU must merge quantities instead of producing a duplicate row (EC-07).
  • degraded records every node that used its fallback, and the response carries it — so a demo that quietly ran without a model is visible rather than mysterious.
  • clarify_rounds is what makes the cycle terminate.
  • verified is false until verify has passed the composed answer. The page renders nothing while it is false, which is how NFR-02 becomes a property of the state machine rather than a discipline.

Routers:

def after_classify(s) -> str:
    if s["shape"] in ("too_short", "digits"): return END       # EC-01, EC-10
    if s["shape"] == "nl":        return "understand_query"
    return "resolve_items"

def after_resolve(s) -> str:
    if not s["resolved"] and not s["candidates"]: return END   # EC-03
    if s["clarify_rounds"] < MAX_CLARIFY_ROUNDS and needs_clarification(s):
        return "clarify"                                       # EC-05
    return "check_availability"

def after_availability(s) -> str:
    return "suggest_substitutes" if any_out_of_stock(s) else "resolve_locations"

def after_locations(s) -> str:
    routable = [i for i in s["basket"] if i.routable]
    if not routable:                                return END          # EC-15
    if len(routable) == 1 or s["mode"] == "single":  return "route_single"  # EC-28
    return "route_multi"

describe_route → verify → END is a plain edge, not a conditional one, and verify has no outgoing branch that skips it. That is deliberate: a conditional edge is a decision someone can get wrong, and there must be no path from a composed answer to the page that does not pass the gate.

8  Search internals

8.1  Index construction

def searchable_text(p: Product) -> str:
    return " ".join([p.name, p.brand, p.size, p.aisle_category, *p.synonyms])

def normalise(text: str) -> list[str]:
    t = unicodedata.normalize("NFKD", text).encode("ascii", "ignore").decode()
    t = t.lower()
    t = re.sub(r"[^a-z0-9%.]+", " ", t)   # keep digits, % and . for "500ml", "1.5l"
    return [tok for tok in t.split() if tok not in STOPWORDS]

index = BM25Okapi([normalise(searchable_text(p)) for p in products], k1=1.2, b=0.5)

b=0.5 rather than the usual 0.75: b controls how hard a long document is penalised, and product names are all short, so the standard value over-penalises the ones that happen to carry synonyms. Both constants belong on the eval set, not in a reviewer's opinion.

8.2  Query classification

SPLIT  = re.compile(r"[,;\n]|\s+and\s+|\s*\+\s*", re.I)
DIGITS = re.compile(r"^\d{8,13}$")
QTY    = re.compile(r"^(\d+)\s*(?:x|×)?\s+(.+)$", re.I)
NL_CUE = re.compile(r"\b(for|with|need|want|make|making|something|what|how|recipe)\b", re.I)

def classify(raw: str) -> tuple[str, list[SearchTerm]]:
    q = " ".join(raw.split())
    if len(q) < MIN_QUERY_CHARS:  return "too_short", []
    if DIGITS.match(q):           return "digits", []          # not a product request
    parts = [p.strip() for p in SPLIT.split(q) if p.strip()]
    if len(parts) > 1:
        return "batch", [parse_qty(p) for p in parts[:MAX_BATCH_TERMS]]   # EC-06
    if len(q.split()) > NL_WORD_THRESHOLD and NL_CUE.search(q):
        return "nl", []
    return "term", [parse_qty(q)]

Order matters, and one rule is deliberately crude. " and " splits before the natural-language test, so "milk and bread" is a batch of two rather than a sentence. The cost: a product with "and" in its name splits wrongly — "salt and vinegar crisps" becomes two terms. The mitigation is cheap: if a split part fails to resolve, retry the unsplit string once before reporting it unresolved. Worth stating, because a reviewer will find this example.

8.3  Ranking

def rank(cands: list[Scored], term: str, stock: dict) -> list[Scored]:
    return sorted(cands, key=lambda c: (
        not stock[c.sku].ranged,          # ranged first — a hard gate
        stock[c.sku].shelf_qty == 0,      # in stock before out of stock
        not variant_match(c.product, term),
        -c.bm25,
        -c.product.popularity,
        not c.product.own_brand,
    ))

A lexicographic tuple sort, not a weighted sum. Weighted sums need tuning and cannot be explained — "why did this rank third" has no short answer. A tuple sort is a precedence list a buyer can read, and it cannot be accidentally mis-tuned into putting an unstocked product first.

8.4  Ambiguity test

def needs_clarification(cands: list[Scored]) -> bool:
    if len(cands) < AMBIGUITY_MIN_HITS: return False
    top, second = cands[0].bm25, cands[1].bm25
    if top <= 0:                        return False
    return (top - second) / top < AMBIGUITY_MARGIN     # 0.15

A relative margin, because BM25 scores are unnormalised and vary with query length — an absolute threshold would fire inconsistently between a one-word and a three-word query.

    sku:    str      # validated against the candidate set
    reason: str = Field(max_length=140)
candidates = [p for p in catalogue.by_category(cat)

              and dietary_compatible(p, original)]      # filter BEFORE the model

choice = model.with_structured_output(SubstituteChoice).invoke(prompt(candidates))
if choice.sku not in {p.sku for p in candidates}:
    raise GroundingError(choice.sku)                    # fall back, never surface

The guardrail is code, not prose. Two mechanisms, both enforced rather than requested. The schema has no field for a product name, so query understanding cannot invent one. And a substitute SKU that was not in the candidate list the service built is rejected outright — the model picks among safe options, it does not nominate them.

dietary_compatible treats a null flag as incompatible when the original product required it. An unknown value never satisfies a dietary requirement.

The verify pass

The two mechanisms above stop the model inventing a fact. verify catches everything downstream of that — a stale cached figure, a mis-joined placement, a template that formatted the wrong leg. Five checks, all against state the services produced:

def verify(s: JourneyState) -> list[Mismatch]:
    m = []
    # 1 every SKU named in the answer was resolved by the search
    # 2 floor, aisle, rack and shelf equal the Placement for that SKU
    # 3 availability wording equals the StockPosition; an unavailable
    #   item has no stop in the route
    # 4 each leg distance and the total equal the plan within ROUND_TOLERANCE_M,
    #   and the floor-change count matches the connectors in the node path
    # 5 every aisle or landmark named in a step appears in the plan's node path
    return m

A non-empty list discards the composed text. The template is rendered from the same service results, verified is set on that, and the mismatch is recorded — never patched in place. Patching would hide the bug that produced it.

10  Routing internals

Single

def route_single(start, placements, step_free):
    target = min(placements, key=lambda p: engine.distance(start, p.node_id, step_free))
    nodes  = engine.path(start, target.node_id, step_free)
    return Route(nodes=nodes,
                 distance_m=engine.distance(start, target.node_id, step_free),
                 floors=floors_touched(nodes),
                 placement=target)

When a SKU has several placements (EC-20) the nearest wins — which is why distance being O(1) matters: evaluating four candidate locations is four array reads.

Multi — floor-clustered, open path per floor, closed at the tills

def route_multi(start, items, end_node, step_free):
    chilled, ambient = partition(items, lambda i: i.location_type == "CHILLER")
    groups = group_by_floor(ambient)                   # {level: [Placement]}
    order  = sorted(groups, reverse=True)              # highest floor first
    legs, cursor = [], start

    for level in order:
        entry = nearest_core(cursor, level, step_free) # arrive at the cheaper core
        seq   = nn_then_2opt(entry, groups[level], step_free)
        legs += [engine.path(cursor, entry, step_free)] + stitch(seq)
        cursor = seq[-1].node_id if seq else entry

    for p in chilled_last(chilled):                    # EC-33
        legs.append(engine.path(cursor, p.node_id, step_free)); cursor = p.node_id

    legs.append(engine.path(cursor, end_node, step_free))   # FR-11, the tills
    return Route(nodes=dedupe_joins(legs), ...)

nn_then_2opt — open path, fixed start

def nn_then_2opt(entry, stops, step_free):
    seq, pool, cur = [], list(stops), entry
    while pool:                                        # nearest neighbour
        nxt = min(pool, key=lambda p: engine.distance(cur, p.node_id, step_free))
        seq.append(nxt); pool.remove(nxt); cur = nxt.node_id

    improved = True
    while improved:                                    # 2-opt, OPEN variant
        improved = False
        for i in range(len(seq) - 1):
            for j in range(i + 2, len(seq)):
                if delta(seq, i, j, entry) < -EPSILON: # no wrap-around term
                    seq[i+1:j+1] = reversed(seq[i+1:j+1])
                    improved = True
    return seq

Open-path 2-opt, not the textbook version. Standard 2-opt optimises a closed tour and its gain calculation includes the edge back to the origin. Each floor leg here is an open path with a fixed start and a free end, so the wrap-around term must be dropped from delta. Using the closed-tour formula produces routes that look subtly wrong — usually a last stop that doubles back — and it is an easy mistake to ship.

11  The Streamlit interface

There is no HTTP layer (C-03). The page calls the compiled graph in the same process, so what would have been a request contract is a function signature.

# app.py — the whole surface between page and graph
GRAPH = build_graph()                      # @st.cache_resource, built once

def run_query(query: str, start_node: str, step_free: bool) -> JourneyState:
    cfg = {"configurable": {"thread_id": st.session_state.thread_id}}
    return GRAPH.invoke(initial_state(query, start_node, step_free), cfg)

def resume(choice: Choice) -> JourneyState:
    cfg = {"configurable": {"thread_id": st.session_state.thread_id}}
    return GRAPH.invoke(Command(resume=choice), cfg)

def plan_route(basket: list[BasketItem]) -> JourneyState:
    cfg = {"configurable": {"thread_id": st.session_state.thread_id}}
    return GRAPH.invoke({"basket": basket, "mode": "multi"}, cfg)

Three mechanics carry what the API used to:

WasIs
POST /journeyrun_query(...) — returns results only, never a route
POST /journey/resumeresume(choice) on the next page run, same thread_id
POST /routeplan_route(basket) — a second graph run, from the basket
GET /journey/{id}GRAPH.get_state(cfg) — the checkpoint is the record (EC-41)
SSE progress streamst.status updated from the node names the graph yields

What the page holds and what it does not. st.session_state holds exactly two things: the thread_id and the basket draft. Everything else is read back from the checkpoint, because Streamlit re-executes the script on every interaction and local state would drift from graph state (EC-36, EC-41).

Caching is load-bearing, not an optimisation. The store, the BM25 index and the distance and predecessor matrices are built in @st.cache_resource builders in ui/resources.py. Without that, every click rebuilds ~314 nodes of all-pairs Dijkstra and NFR-05's five seconds are gone before the search starts.

The search box lives inside st.form, so the graph is invoked on submit rather than on each keystroke.

Thread lifetime. A thread_id is minted per search and swept after THREAD_TTL_MINUTES (§14). LangGraph does not expire threads, so without the sweep every abandoned clarification leaks a checkpoint (EC-34).

The split that matters: a data error stops the service, a model error degrades one node. Nothing in the second class can produce a wrong location or a wrong stock figure, because no model sits on those paths.

13  Startup validation

The rules live in schema.md §7 — forty-seven checks, V-01 to V-47, which supersede the eleven this section used to list. They are schema territory: what makes a store folder well formed is a property of the format, not of this application. What belongs here is when they run, in what order, and what happens when one fails.

validation.py runs them inside the @st.cache_resource builder that loads the store, which means they run once per process, before the first search, and a failure raises rather than returning a half-loaded store.

PhaseChecksWhy this order
1 · ParseColumn presence, types, encodingsNothing else can run against a file that will not parse
2 · Within-fileUniqueness, ranges, enum membershipCheap, and catches most hand-authoring errors
3 · ReferentialPlacement → SKU, placement → map node, stock → SKUNeeds every file loaded, so it cannot come earlier
4 · GraphConnectivity, positive weights, every floor reachable, lift-only subgraph connectedNeeds the graph built, which needs phase 3 to have passed
5 · Store shapeAt least one checkout node, levels agree with the mapLast, because it is the only phase that encodes a requirement rather than a data rule

Phase 4 is the one worth naming in a review: the lift-only subgraph is checked for connectivity separately, because a store can be perfectly walkable and still have no step-free path between two floors. FR-19 would then be unsatisfiable at runtime, and the shopper would be the one to discover it.

A failure names the file, the row and the rule. StoreDataError is the only error in §12 that refuses to start.

The test that matters most is the fallback suite. It is the only thing that proves the claim the whole design rests on — that a model failure degrades fluency and never correctness. Forcing each of the three model nodes to fail and asserting the journey still returns a correct location and a correct route is what turns that from an assertion into a fact.
