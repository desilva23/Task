Product Finder Requirements

Multi-floor store product finder and navigation agent. What the system must do, and how each requirement is verified.

Requirements 24 functional · 11 non-functional Constraints 5

1  Overview

Shoppers in a large multi-floor store lose time hunting for products and cannot tell from the shelf whether an item is stocked at that branch. This system takes one or more typed product requests and returns, for each, whether it is available, exactly where it sits, and the shortest walking route to reach it — including floor changes.

It is built as an agentic system in which language models interpret and phrase, and deterministic tools supply every fact. It must work on any store by replacing the store data, with no code changes.

In scope

  • Typed product requests — single, several at once, or natural language
  • Product matching against a store catalogue
  • Availability from a mock inventory file
  • Product location to floor, aisle, rack and shelf
  • Shortest route from any start point in the store, across floors
  • One combined route for several products
  • Step-free routing
  • A single-page user interface

Out of scope

  • Voice input
  • Live shopper positioning — beacons, Wi-Fi, QR markers
  • Integration with any real inventory, planogram or mapping system
  • Payments, loyalty and recommendations
  • Shelf-compliance detection from photographs
  • More than one store running concurrently
  • Colleague workflows — order picking, replenishment, shelf-edge tasks

Inputs

One store folder holding four kinds of data: the store map (walkable points, paths between them, and the stairs and lifts connecting floors), the product catalogue, the planogram (which product sits on which shelf) and the stock position. File format and structure are specified in the Schema document, not here — the map may take more than one file, since a graph does not fit a single table.

Done when

A shopper's request returns the correct availability, the correct location and a provably shortest route — including from a start point other than the entrance, and across floors; every fact in every answer has been checked against the store data before it is shown; and a second, differently shaped store works with no code changes.

5  Non-functional requirements

IDAreaRequirement
NFR-01CorrectnessAvailability, location, distance and directions are taken only from the store data. No fact in any answer is generated by a language model.
NFR-02VerificationEvery factual claim in a response is checked against the store data before it is shown. A claim that fails the check is never displayed.
NFR-03SafetyNo generated text asserts that a product is gluten free, nut free, vegan or halal. Such claims come only from a recorded product attribute, passed through unaltered. An unrecorded attribute reads as unknown, never as absent.
NFR-04ReliabilityIf a language model is unavailable, slow, or returns malformed output, the system still answers using deterministic rules. The answer may be less fluent; it is never less correct.
NFR-05PerformanceUnder 5 seconds for one product; under 10 seconds for ten products.
NFR-06Input safetyEmpty, over-long, non-English, duplicated and deliberately malicious input is handled safely. Shopper text cannot alter which tools run, nor reach files or commands.
NFR-07Data integrityInvalid or inconsistent store data is rejected when the store is loaded, not discovered during a shopper's request.
NFR-08PortabilityA differently shaped store passes the same acceptance tests with no code changes.
NFR-09ExplainabilityWhy a product ranked where it did, and why a route took the order it did, can both be explained without reference to a model.
NFR-10AccessibilityStep-free routing is available, and route directions are usable by a screen reader.
NFR-11Mobile layoutThe interface is usable at phone width — roughly 390 px — in a mobile browser: no horizontal page scrolling, controls reachable one-handed, and the floor map legible without pinch-zoom.

7  Situations the system must handle

Required behaviours, not solutions. Each becomes a test case.

Input

  • Empty, one character, or extremely long
  • Misspelled — "paracetomol", "yoghurt"
  • Non-English text, emoji, punctuation only
  • Many items at once; duplicated items; quantities ("2 x milk")
  • Text that is not a product request at all
  • Text written to subvert the system's instructions

Matching

  • Synonyms and colloquial names — "coke", "nappies", "kitchen roll"
  • Several sizes or variants of the same product
  • A generic word that is a category rather than a product — "milk", "dairy"
  • A product held in two places at once
  • A product in the catalogue but absent from the planogram
  • A product in the catalogue but not stocked at this branch

Start point

  • The entrance; any other aisle; an unrecognised location
  • Standing on a staircase or in a lift lobby
  • Already standing at the product

Routing

  • Same floor; different floor; every floor
  • A connector out of service
  • Step-free requested where no step-free path exists
  • A single item submitted as a multi-product request
  • Chilled and frozen items that should be collected last

Several products

  • Spread across all floors
  • One unavailable; all unavailable
  • One ambiguous while the others resolve cleanly
  • A list long enough to need a cap

Data and system failures

  • Store map with an unreachable point, a missing point, or duplicate identifiers
  • Planogram referring to a product or a location that does not exist
  • A model returning malformed output, or declining the request
  • A tool failing or timing out
  • A wrong aisle or a wrong distance caught before the shopper sees it
  • A shopper abandoning a choice prompt and never returning

8  Glossary

SKUThe store's unique code for one exact product, including size and variant
PlanogramThe shelf-level layout plan: which product sits on which shelf. It records where a product is supposed to be, which is not the same as where it is
Bay / rackOne section of a shelving unit within an aisle. "Rack" is used throughout this document
FacingOne product's frontage on a shelf. A product may hold several adjacent facings
RangedCarried by this particular branch. A product can be in the catalogue without being ranged here
ConnectorA staircase or a lift joining two floors
Step-freeA route using no stairs — between floors, one that travels by lift
