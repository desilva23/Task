# Project context

Read this first. It carries the decisions and their reasoning from the session
that produced this repository, so they do not get re-litigated.

## What this is

A **proof of concept** for an in-store product finder and navigation agent.
A shopper types one or more products — or scans a barcode — and gets, for each: whether it is
available, where it is (floor, aisle, rack, shelf), and the shortest walking
route to it, across floors. Built as an agentic system on synthetic data.

**Current state: built, tested and deployed on Streamlit** — https://weurhd8vy4j68dmbhcbkd6.streamlit.app.
Phase 10 (on `feature/nextjs`) replaces the Streamlit page with Next.js on Vercel; until it is
merged and deployed, the Streamlit app is the live one.
The four design documents are the specification. The rules for building against
them are in `.specify/memory/constitution.md` — read it before writing code.
Work proceeds in phases 0–10 (see **Pending work**), and the owner reviews each
phase at a gate before the next one starts.

## Document ownership — four documents, kept separate

This separation is deliberate and was asked for explicitly. Do not merge them.

| Document | Owns | Must not contain |
|---|---|---|
| `docs/requirements.md` | What the system must do. FR/NFR/AC/OQ register | Architecture, algorithms, schemas, technology choices beyond the stated constraints |
| `docs/hld.md` | Component architecture, agent decomposition, search design, interface, edge cases | Requirements (they live in requirements.md), field-level schemas |
| `docs/lld.md` | Module layout, signatures, algorithms, thresholds | Requirements, and the data schemas — §2 and §3 are now stubs pointing at `schema.md` |
| `docs/schema.md` | The six store CSVs, columns, identifier scheme, referential rules, load-time validation | Requirements, architecture, algorithms |

A requirement that names a technique cannot be challenged without re-opening the
design; a design hiding inside a requirement never gets reviewed. That is why
they are apart.

`docs/pages/*.html` are the rendered versions of these documents, published as
artifacts. **They duplicate the markdown and will drift.** Treat the markdown as
the source of truth and update the HTML alongside it, or stop maintaining the
HTML — but do not let them silently disagree.

Older documents (`proposed-scope.md`, `architecture.md`,
`use-case-understanding.md`, `clarifying-questions.md`, `solution-sketch.md`,
`genai-opportunities.md`) predate the four-document split and the build. Each opens
with a **historical** note saying what no longer matches; they are kept for their
reasoning, not maintained. Never treat them as the current design.

## Settled decisions — do not re-open without being asked

| Decision | Reasoning |
|---|---|
| **LangGraph** orchestrates the whole pipeline, including deterministic steps | Mandated. Deterministic steps become plain-function nodes; the generated graph is then the architecture diagram and cannot drift from code |
| **Next.js page + stateless FastAPI function** (C-03), replacing Streamlit | Owner's change, 2026-10-14. The page is a static export; `/api/*` is one Python function. **Stateless**: each request builds a journey (~4 ms) on a fresh thread and deletes it before answering; the page holds position, basket and clarification answers, and a clarification is answered by resending the search with the answers (`Journey.answer`). Services needed no change — they never carried a web dependency, which is what made this cheap |
| **Dijkstra from every node at startup**, not per request | Layout is static, so all-pairs shortest paths precompute once; every query is an O(1) matrix lookup |
| **Not A\*** | It optimises a single query, and across floors straight-line distance is not an admissible heuristic — a route cannot pass through a ceiling |
| **BM25** for search, not vector search | At ~200 SKUs the structured filter handles semantic cases more cheaply and explainably. Hybrid BM25 + embeddings with reciprocal rank fusion is the scale-up path, not the starting point. **Measured in Phase 4** (`scripts/search_eval.py`): exact, typo, synonym, category and multi-item queries all land; meaning-style sentences go to the model and are never asserted by keyword match |
| **Lexicographic tuple sort** for ranking, not a weighted sum | A weighted sum cannot answer "why did this rank third" and can be mis-tuned into ranking an unstocked product first |
| **Three floors** for the demo, two for the portability store | Three is the smallest store where the fixed floor order is a real decision. Catalogue and planogram do not grow with floor count — only the map does |
| **Fixed floor order**, one picking pass per floor, ending at a checkout | A distance-only optimiser sends shoppers up and down repeatedly |
| **Basket gate** — batch results grouped by availability, one action moves only in-stock items | The basket, not the search result, is what gets routed, so no route is planned to an empty shelf |
| **Rack-level addressing**, graph stops at rack | A shelf is not somewhere you walk. ~300 nodes instead of ~1,200, and directions can still name a shelf |
| **Stairs and lifts** between floors, no escalators | A lift is the only step-free way between floors, so without one FR-19 is unsatisfiable. Escalators added a third edge kind for no requirement |
| **Barcode scan — FR-03 reinstated** | Withdrawn during review, reinstated by the owner 2026-10-14 under the same ID. Decoded **live in the browser** with zxing-wasm (WASM served from our origin), behind a "Scan a barcode" switch; only digits reach the server, which re-checks them. Typed digits beside the camera are the same lookup. (Phase 9 decoded a still photo on the server; Phase 10 moved decoding to the phone.) A barcode is an **exact** lookup — never ranked, fuzzed or matched to a nearest product. The scan enters the graph at `classify_query` (`action = "scan"`), so no node was added. The demo barcodes are GS1 `20` in-store numbers, so a real product's barcode correctly reports "not in this store's catalogue" |
| **CSV** for the data files, map as two CSVs | Authorable in a spreadsheet, readable without a parser. A graph does not fit one table |
| **GroqCloud** is the model provider (C-06), via `langchain-groq` | Owner's choice. Schema-bound calls need strict structured output, which only `openai/gpt-oss-20b` and `-120b` offer — 20b for understand/describe, 120b for substitutes. IDs live in config (`lld.md` §14) |
| **Vercel** for deployment (C-07), replacing Streamlit Community Cloud | Owner's change, 2026-10-14. Hobby plan, free for non-commercial use. One project: Next.js static files plus `api/index.py`; `vercel.json` routes `/api/*` and trims the function bundle. Python 3.12 from `.python-version` and `pyproject.toml` |
| **GitHub Spec Kit**, test-first, bottom-up, gated phases | Owner's choice. Each phase is one Spec Kit feature under `specs/`; every test names the AC/FR/NFR/EC/V ID it proves |
| **uv + ruff + pytest**, Python 3.12 | One lock file, one linter/formatter. The machine has 3.14; do not let it leak into the lock |
| **A seeded generator** produces the synthetic store | Same seed, same store — tests and the demo can rely on exact SKUs and positions |
| **No store or synthetic-data line on the page** | Owner's decision, 2026-10-14. C-04 now says the store files declare the data synthetic (V-12 enforces it); the page does not repeat it |

## The rule the whole design rests on

**The model interprets and phrases. It never supplies a fact.**

Locations, stock figures and distances come from the data via deterministic
code. A hallucinated aisle number sends a shopper to the wrong floor. Enforced
in types, not prose: `ParsedQuery` has no field for a product name, and a
substitute SKU outside the candidate set the service built is rejected.

Corollary: **allergen and dietary claims are never generated.** They come from a
recorded attribute, passed through verbatim. A `null` dietary flag means
*unknown*, never *absent* — collapsing null to false would silently assert "not
gluten free" about products nobody checked.

## Things not to do

- **Do not train a model on the store map.** It is a fact to look up, not a
  pattern to learn. A model that has "learned" the map invents aisle numbers for
  products it did not memorise. This is not a machine learning problem.
- **Do not use a ReAct agent that decides which tool to call.** The sequence is
  known; use explicit edges.
- **Do not promise the colleague-facing version.** It is out of scope and a
  different problem, not a later phase. Kept out of the requirements deliberately
  so it does not read as a commitment.
- **Do not put a schedule in the requirements document.** A timebox is a project
  fact, not a requirement, and cannot be tested.

## Known traps

| Trap | Why |
|---|---|
| A Llama model for a schema-bound call | On GroqCloud only the gpt-oss models enforce a JSON schema strictly; Llama gives JSON mode, not the schema |
| Streaming or tools with structured output | Groq does not support either alongside structured output. Neither is needed here |
| `with_structured_output(strict=True)` on gpt-oss | A LangChain bug (langchain#34155) breaks it. Pass Groq's `response_format` straight through `ChatGroq.invoke` and validate the JSON ourselves |
| Constraint keywords in a strict schema | Groq strict mode needs every property `required` and `additionalProperties: false`, and does not document `maxLength`, `default` and friends — they are stripped from the schema sent and enforced by our own validation |
| `max_tokens` set too low | gpt-oss reasons before answering and that counts against the cap — the reply truncates mid-JSON |
| Committing `GROQ_API_KEY` | The repo is public. Key goes in `.streamlit/secrets.toml` locally (gitignored, kept for that one line) or a Vercel environment variable; a test fails if either secrets file is tracked. The key never reaches the page |
| A public app spending the owner's key | The per-visitor cap is a cookie count — clearing cookies resets it. The binding guards are the Groq spend limit and a Vercel firewall rate limit on `/api/*` |
| Groq free-tier rate limit | 8,000 tokens/minute on gpt-oss-20b (measured 2026-10-14). Repeated live test runs exhaust it and later calls 429 into the fallbacks — run `pytest -m live` once per minute |
| `dangerouslySetInnerHTML` for anything but the floor plates | The plates are SVG our code drew from validated data. Every other string can hold the shopper's or the model's words — render it as React text, never as markup (AC-13) |
| Starting the camera on page load | It asks permission at once — keep `getUserMedia` behind the switch, and stop the tracks at the first read |
| Keeping state in the API between requests | Vercel may send the next request to another instance. Anything the next request needs comes from the page |
| `rewrites` with `output: "export"` | Next.js refuses them. `next.config.mjs` proxies `/api` only under `next dev`; on Vercel, `vercel.json` routes it |
| Camera over plain HTTP | Browsers refuse the camera outside a secure context (C-08). `localhost` counts as secure; a LAN IP does not — use the typed digits there |
| Building services per request | The store, BM25 index and distance matrices are built once per function instance (`api.index.services`, cached); only the cheap journey is per request |
| Textbook closed-tour 2-opt | Each floor leg is an **open** path with a fixed start; the wrap-around term must come out of the gain calculation |
| Abandoned clarifications | LangGraph does not expire threads. The API deletes each request's thread before answering (`Journey.forget`) |
| `MemorySaver` vs `InMemorySaver` | Export name differs by release. Pin versions and check what is actually exported |

## Conventions

- Requirement IDs are stable, including across withdrawals — FR-03 was withdrawn,
  left as a gap, and reinstated under the same number.
- **Open questions do not live in the requirements.** They are parked in
  `notes/internal_notes.md` so the specification contains only committed scope
  and reads as no promise of future work. A question that gets *answered*
  becomes a constraint or an assumption in the requirements, with its reasoning.
- Every requirement has an acceptance criterion. One without is not finished.
- Every test cites the ID it proves, in its name (`test_ac_01_…`) or docstring (`AC-01`) —
  `AC`, `FR`, `NFR`, `C`, `A`, `EC`, `V`, `W`, or `CONST-<principle>` for a test that enforces the
  constitution. Collection fails otherwise. `docs/traceability.md` is generated by
  `scripts/trace_matrix.py`; never edit it by hand.
- `notes/` is **gitignored** — internal notes stay out of this public repo. If
  that file is missing locally, it was never in git; ask the owner for it.
